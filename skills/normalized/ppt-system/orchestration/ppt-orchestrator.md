# PPT Orchestrator System

## Mission

Generate professional presentation systems through staged skill orchestration.  
The system formalizes presentation design into explicit cognitive, narrative, and visual rules to produce slides that are structured, coherent, and visually consistent.

---

## Presentation Philosophy

### Presentations are not documents
Slides are visual aids for live communication. They should support the speaker rather than replace them. Without a presenter, slides should not fully carry meaning on their own.

### One slide, one core idea
Each slide communicates a single message. If multiple ideas appear, split the slide.

### Visual hierarchy guides attention
Typography, contrast, spacing, and alignment guide cognitive focus. White space is a functional design element that improves clarity.

### Simplicity reduces cognitive load
Avoid dense paragraphs. Prefer concise statements and structured fragments. A slide should typically be explainable within ~1 minute.

---

## Slide Responsibility System

Each slide must serve one primary function:

- **Introduction** — context or topic framing
- **Comparison** — contrast between elements
- **Explanation** — concept, model, or process clarification
- **Persuasion** — argument or recommendation
- **Transition** — bridge between sections
- **Summary** — consolidation of insights
- **Emphasis** — highlight a single critical statement

### Common Slide Patterns

- **Comparison Slide**
  - Side-by-side layout (50/50 split)
  - Minimal items per side

- **Process Slide**
  - Sequential steps
  - Arrows / numbering / timeline

- **Metrics Slide**
  - Single dominant KPI
  - Large number + minimal text

- **Quote Slide**
  - Full-screen text emphasis
  - Optional background visual

---

## Narrative Flow Rules

- Maintain progressive storytelling (no static repetition)
- Alternate slide types for cognitive variation
- Ensure each slide naturally leads to the next
- Recommended structure:
  - Problem → Insight → Evidence → Solution → Decision

---

## Layout Decision Rules

- **Comparison** → 50/50 split layout
- **Process** → timeline / step flow layout
- **Metrics** → large-number focus layout
- **Emphasis** → full-screen text or image overlay
- **Frameworks** → hierarchical diagram layout

---

## Slide Grammar Library

Standardized reusable slide types:

- Comparison
- Process
- Metrics
- Quote / Emphasis
- Framework / Model

Each grammar defines:
- Use case
- Layout pattern
- Content constraints
- Visual expectations

---

## Visual Consistency Policy

- **Fonts**: max 2 font families per deck
- **Colors**: 1–2 primary colors + neutral palette
- **Alignment**: strict grid system
- **Spacing**: consistent margins and rhythm
- **Charts**: unified styling across all visuals

Consistency reduces cognitive load and improves readability.

---

## Skill Routing Rules

- storytelling → `storytelling-skill`
- aesthetic refinement → `taste-skill`
- HTML slide generation → `frontend-slides`
- spacing / hierarchy polish → `frontend-polish`

---

## Execution Rules

- Do not start visual design before narrative stabilizes
- Do not generate layout before slide grammar assignment
- Maintain visual consistency across all slides
- Enforce structural-first, design-second workflow

---

## Workflow Stages

1. Requirement Analysis
2. Narrative Planning
3. Slide Grammar Assignment
4. Layout Generation
5. Visual Refinement
6. Consistency Checking
7. Export Rendering

---

## System Objective

The PPT Orchestrator System formalizes presentation design into a staged cognitive pipeline.  
It ensures slide generation is structurally grounded, narratively coherent, and visually consistent rather than purely aesthetic.
