# Framework / Model Slide Grammar

## Use Case

Present a conceptual structure — a model, framework, matrix, or system of ideas with defined relationships. The audience should understand both the components and how they relate to each other.

Typical scenarios:
- Business model or strategy framework (e.g., SWOT, Porter's Five Forces)
- System architecture or component diagram
- Conceptual model (e.g., a 3-layer stack, a virtuous cycle)
- Classification or taxonomy
- Mental model or decision framework

## Narrative Role

- **explanation** — makes an abstract structure concrete
- **framing** — provides the lens through which to interpret subsequent content
- **orientation** — gives the audience a mental map to navigate the topic

## Layout Pattern

**Hierarchical diagram layout** — spatial arrangement encodes conceptual relationships.

Common spatial patterns:
- **Stack** (vertical layers) — hierarchy, dependency, foundation → surface
- **Matrix** (2×2 or 3×3 grid) — two-axis classification
- **Hub and spoke** — central concept with radiating elements
- **Cycle** (circular flow) — repeating process or virtuous/vicious cycle
- **Pyramid** (triangular hierarchy) — bottom-up or top-down structure
- **Venn** (overlapping sets) — intersection and overlap of concepts

Each node contains:
- Concept label (short)
- Optional: 3–5 word descriptor

Connectors between nodes show:
- Hierarchy (parent → child)
- Flow (direction)
- Dependency (dashed line)
- Grouping (containment)

## Information Density

**Medium.** The structure itself carries meaning, so node count is constrained by spatial clarity.

Maximum:
- 3–5 primary nodes (top-level concepts)
- Each node: label + optional brief descriptor
- Connections must remain visually traceable (avoid crossed lines)

## Content Constraints

- Framework nodes must be **same-level abstractions** — don't mix "Industry Forces" with "Check competitor pricing"
- Node labels are **conceptual nouns** (e.g., "Market Demand" not "People want more of this")
- Every connection must represent a **real relationship** — don't connect nodes just for visual symmetry
- If using a matrix, both axes must be clearly labeled
- The framework must be **named** (e.g., "Porter's Five Forces") or clearly positioned as the presentation's own framing

## Cognitive Goal

Enable the audience to **internalize the structure** — they should be able to recall the framework's shape and key nodes after the presentation. The spatial layout should reinforce the conceptual relationships.

## Visual Expectations

- The structure is immediately recognizable (stack, cycle, matrix, etc.)
- Node hierarchy is visually encoded (size, position, color intensity)
- Connectors are clean and purposeful — no decorative flourishes
- Labels are legible within nodes (adequate contrast and size)
- The framework occupies the majority of the slide — it is the content, not a decoration

## Avoid

- Overcomplicated diagrams (8+ nodes, crossed lines)
- Unlabeled connectors or ambiguous relationships
- Mixed spatial metaphors (stack + cycle on one slide confuses)
- Nodes with paragraph-level text
- Purely decorative frameworks that don't aid understanding
- Unnamed or unpositioned models (the audience asks "whose framework is this?")
